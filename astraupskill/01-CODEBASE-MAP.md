# Codebase map

The ticket workflow crosses a small set of deliberate boundaries. [ticketRoutes.ts](../apps/api/src/modules/tickets/ticketRoutes.ts) owns Express routing and JSON parsing. It calls the service with `req.auth`, which was populated by [auth.ts](../apps/api/src/middleware/auth.ts). The route does not decide whether a priority-only edit is permitted; that decision belongs in [ticketService.ts](../apps/api/src/modules/tickets/ticketService.ts), where every caller receives the same rule.

`updateTicket` begins by checking `canEditTicket`. This matters because `updateTicketSchema` accepts a partial object, including `{}`. A viewer must receive 403 before the service performs the `findFirst`, so the forbidden request cannot read a row or accidentally create an audit or outbox record. For an operational actor, the service loads the ticket with `tenantId: auth.tenantId`, validates a status transition with `assertTicketTransition`, validates an assignee with a tenant and active predicate, and then starts the Prisma serializable transaction.

The [domain package](../packages/domain/src/index.ts) contains pure role and workflow decisions. `canViewInternalNote` describes comment visibility, `canEditTicket` describes ticket PATCH authority, and `canAssignTicket` preserves the narrower assignment vocabulary used by existing callers. The [shared package](../packages/shared/src/index.ts) describes the allowed wire shape: status, priority, nullable assignee, and tags. Zod rejects malformed values before the service, while the service still protects itself from non-HTTP callers.

The [Prisma schema](../prisma/schema.prisma) defines tenant foreign keys and indexes. `ticketIncludeForRole` applies the same comment predicate to a returned update that `getTicket` applies to a read. `createTicket` and `updateTicket` write the ticket, `AuditLog`, and `OutboxEvent` in one `$transaction` with serializable isolation. The worker reads pending outbox rows in [worker.ts](../apps/worker/src/worker.ts). Follow this call graph when debugging: request headers → auth context → route schema → service authorization → tenant query → domain validation → transaction → role-shaped response.
